# ARPO Bot

AI assistant for Bharat Scouts & Guides (BSG India). ARPO answers scouting queries by retrieving context from official APRO rulebooks and provides syllabus trackers and badge identification.

## Features

- **Document Retrieval (RAG)**: Queries are embedded and searched against indexed APRO PDFs in Pinecone. The bot is instructed to cite the source file and page number for every factual claim.
- **Hinglish Responses**: Enforced at the system prompt level to reply in a conversational Hindi-English mix.
- **Badge Identification**: Processes uploaded badge images using `gemini-2.0-flash` to extract visual elements, which are then used as a vector search query against the Pinecone index to retrieve requirements.
- **Rate Limiting**: Enforces a limit of 5 questions per hour per user (unlimited for admins).
- **Admin Document Indexing**: Dedicated routes to upload and index new APRO PDFs.

## Architecture

- **Frontend**: Next.js 16, React 19, Tailwind CSS v4.
- **Backend**: Express running on Bun.
- **Database**: MongoDB (Mongoose) for user accounts, chat threads, and message history.
- **Vector Store**: Pinecone (`@langchain/pinecone`), storing 768-dimensional embeddings generated by `gemini-embedding-001`.
- **LLM**: Google Gemini API (`gemini-2.0-flash`) for chat completions and image analysis.

### Query Flow
1. User sends a message (text or image) to `POST /api/v1/chats`.
2. If an image is present, the backend encodes it in base64 and prompts Gemini to describe the visual elements.
3. The text query (or image description) is embedded and used to query Pinecone for the top 8 relevant document chunks.
4. Retrieved documents, recent chat history (from MongoDB), and the current query are sent to Gemini.
5. The cited answer is returned and appended to the MongoDB thread.

## Local Development

**Prerequisites:** Bun, Node.js, a Pinecone index (768 dimensions), a MongoDB cluster, and a Google AI API key.

### Backend Setup

```bash
cd backend
bun install
cp .env.example .env
```

Configure the `.env` file with your credentials (see `backend/.env.example`).

Start the Express server:
```bash
bun dev
```
The API runs on `http://localhost:3001`.

### Frontend Setup

```bash
cd frontend
bun install
cp .env.example .env.local
```

Ensure `NEXT_PUBLIC_API_URL` points to your backend.

Start the Next.js development server:
```bash
bun dev
```
The app runs on `http://localhost:3000`.
